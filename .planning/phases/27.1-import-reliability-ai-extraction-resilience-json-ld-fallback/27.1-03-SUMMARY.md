# Phase 27.1 Plan 03: Failure surfacing — unconditional emit + dismissible error card Summary

**`handleJobFailed` now guarantees the `failed` realtime event fires and stays cookbook-scoped even when cleanup or scope resolution throws, and a failed import renders a real, dismissible error card in the dashboard grid instead of an eternal skeleton, in all 12 locales.**

## Performance

- **Duration:** ~70 min
- **Completed:** 2026-07-28
- **Tasks:** 3 / 3 completed
- **Files modified:** 18 (4 created, 14 modified, including 12 locale `common.json` files)

## Accomplishments

- `handleJobFailed` (`packages/queue/src/recipe-import/worker.ts`) rewritten: the `failed` emit now happens BEFORE `deleteRecipeImagesDir`, each step is independently `try`/`catch`-guarded, and the whole function is wrapped so it can never reject — `lazy-worker-manager.ts:259-263` only logs an `onFailed` rejection, which is exactly how the event used to disappear silently.
- A rejecting `resolveHouseholdRealtimeScope` now falls back to `{ viewPolicy: "owner", ctx: { userId, householdKey } }` — the narrowest scope, reaching only the importer — never widening. A healthy resolution keeps the SAME household scope `importStarted` used, so the event that removes a shared-cookbook skeleton reaches the same audience that saw it appear.
- `packages/queue/__tests__/recipe-import/failed-emit-isolation.test.ts` (12 new tests, real `emitByPolicy`, mocked resolver/cleanup): throwing cleanup, throwing resolver, both throwing, throwing emit, non-final failure (no emit, cleanup still runs), `job === undefined`, `describe.each(["household","everyone"])` proving no `broadcast` and the target cookbook's key, and a personal-import (`householdId: null`) case under both policies.
- **Adversarial verification performed and reverted.** Temporarily routed `viewPolicy === "everyone"` to `emitter.broadcast()` inside `emitByPolicy` (`packages/shared-server/src/realtime/policy.ts`). Confirmed RED: 5 tests failed across three files — `failed-emit-isolation.test.ts` (the new `everyone` sibling), `progress-isolation.test.ts` (phase-24's existing `everyone` sibling), and `cook-source-isolation.test.ts` (phase-27-W3's `everyone` cases, 2 tests) — proving the isolation suites actually exercise the boundary rather than being vacuous. Reverted via `cp` from a pre-edit backup; `sha256sum` before/after identical (`fd7d3114631ea5ccd1a53f19c9f08120cdaed8538b6a14bd4c4dd1caa1e3f291`), and `git status --short packages/shared-server/src/realtime/policy.ts` was empty afterward. The weakening was never staged or committed.
- Client-only `FAILED_IMPORTS_QUERY_KEY` cache added to `use-recipes-cache.ts`, mirroring `IMPORT_STAGES_QUERY_KEY` (`staleTime`/`gcTime: Infinity`, all refetch disabled, no server `queryFn` — a `failed` job is removed from Redis via `removeOnFail: true`, so the realtime event is the only carrier). `addFailedImport`/`dismissFailedImport` helpers added; threaded through `use-pending-recipes-query.ts`, `use-recipes-query.ts` (and its barrel `index.ts`), both `recipes-context.tsx` files (shared-react + apps/web), and finally `recipe-grid.tsx`.
- `use-recipes-subscription.ts`'s `onFailed` now calls `addFailedImport` BEFORE `removePendingRecipe` — recording after removal would race the grid into showing neither a skeleton nor a card for one render. The existing toast (`callbacks.onFailed?.(payload)`) is unchanged, in addition to the card, not instead of it. `onImported`/`onCreated` now call `dismissFailedImport` for the landing id, so a successful retry clears a stale card.
- `FailedImportCard` (new, `apps/web/components/dashboard/failed-import-card.tsx`): a memoized client component matching `RecipeCardSkeleton`'s exact geometry (`h-[340px]` grid / `h-[128px]` list) so the grid never reflows when a skeleton becomes a card. Shows a danger-toned header, the translated title, the failure reason (or a translated fallback when the server sends none), the source URL's HOST only (never the raw URL/remote text), and an accessible dismiss button. Every string is a `useTranslations("common.import.failure")` call — manually confirmed no literal English string is rendered (all `text-*` matches in a grep pass are Tailwind classNames, not rendered text).
- `recipe-grid.tsx`'s `displayData` now yields a third shape (`{ id, isFailed, reason, url }`) alongside pending skeletons and recipes; a failed id is excluded from the pending-skeleton list (already true because `onFailed` removed it from `pendingRecipeIds`) and `renderItem` returns `FailedImportCard` for it, with `failedImports`/`dismissFailedImport` added to the `useMemo`/`useCallback` dependency arrays.
- `common.import.failure` block (title, fallbackReason, source, dismiss) added to all 12 locales as a sibling of `common.import.progress`. `de-formal` uses Sie-conjugated verbs ("versuchen Sie"), `de-informal` uses du-conjugated verbs ("versuche") in `fallbackReason` — a genuine difference, not a copy-paste (proven by `JSON.stringify(a) !== JSON.stringify(b)`).
- `apps/mobile` untouched and additive-only: `SharedRecipesContextValue` (spread via `...base` in both `apps/web/context/recipes-context.tsx` and `apps/mobile/src/context/recipes-context.tsx`) automatically carries the two new fields; `pnpm --filter @norish/mobile typecheck` is clean with zero mobile-side edits.

## Issues Encountered

- The plan's own literal Task 3 acceptance-criteria node command (`m.common.import.failure`) doesn't match the actual JSON shape — `common.json`'s top-level keys are NOT nested under a `"common"` wrapper key (the `common` namespace comes from the directory name, not an in-file wrapper). Ran the corrected form (`m.import.failure`) instead; the corrected command confirms all 12 locales report exactly 4 keys.
- `vi.clearAllMocks()` in a `beforeEach` clears mock call history but does NOT restore a `vi.spyOn(...).mockImplementation(...)` set inside a single test (`failed-emit-isolation.test.ts`'s "the emit itself throws" case), which leaked a broadcast-throwing `emitToHousehold` spy into the next test and caused 2 spurious failures. Fixed by adding `afterEach(() => vi.restoreAllMocks())`.
